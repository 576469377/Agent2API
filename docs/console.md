# 控制台

[文档导航](README.md) · [快速开始](quickstart.md) · [故障排查](troubleshooting.md)

控制台使用本地 HTML、CSS 和 JavaScript，不依赖前端构建工具。常规页面不访问 CDN；对话中的数学公式保留原有 KaTeX 按需加载，离线时显示原文。九个页面按监控、资源、工具与设置分组，共享已接入平台的数据，目前包含 WorkBuddy 国内版与国际版：

界面采用中性深色 / 浅白主题与蓝色操作强调，统一导航、资源面板、表格和弹窗。桌面侧栏可收起为图标导航，手机保留抽屉导航；平台页可直接进入该平台的账号或模型。具体约定见[控制台视觉规范](design/console.md)，调研依据与分阶段安排见[优化计划](design/2026-10-14-console-plan.md)。

- **概览**：四项核心指标可切换累计 / 15 / 30 分钟；流量趋势、平台账号就绪分布、独立的响应表现与累计调用占比、最近调用与异常处理入口。
- **调用日志**：组合筛选平台、协议、状态、模型、账号、时间和关键词；按时间、耗时或 Token 排序，20 / 50 / 100 条分页，详情与筛选结果 CSV 导出。
- **用量分析**：首屏显示累计调用与输入 / 输出 Token、实时生成状态和年度活动图。每日趋势提供近 7 / 30 天、全部记录、平台筛选与模型占比；热图支持每日 / 每周 / 累计。累计分布、分组明细、搜索与 CSV 导出通过「累计明细」展开；采集口径、覆盖状态和归档来源可从「统计口径」查看。
- **账号管理**：表格与卡片切换，集中查看凭证状态、账号与模型冷却、并发、累计用量并进入账号日志；保留添加、启停和重新登录。
- **平台连接**：连接与账号情况，以及裸模型名优先级、同名模型回退和固定平台的路由说明。
- **模型目录**：按平台、能力与费率筛选，显示上游积分倍率并按倍率排序；完整模型 ID 复制、详情、直接进入测试，以及模型 × 账号可用性矩阵。
- **模型测试**：指定平台或自动路由、流式回复、思考内容、生成参数与停止生成。
- **客户端接入**：选择三种协议与真实模型路由 ID，复制网关地址和请求示例；示例只使用占位值，不插入浏览器保存的密钥。
- **设置**：真实网关地址、控制台连接凭据、运行参数与可热更新的平台脱敏开关。

深浅主题、中英文、账号视图、更新间隔与浏览器连接凭据保留在浏览器本地。状态支持每 10 / 30 / 60 秒自动更新或手动更新，页面隐藏或弹窗打开时暂停自动更新；上游模型费率每分钟独立更新；目录在进入页面或手动更新时也会重新获取。顶部搜索或 `Ctrl / Cmd + K` 可快速进入页面、模型测试与账号详情。

模型页提供费率数量概览：点击零积分、积分计费、浮动或未知可联动筛选；数量按当前平台、能力与搜索计算，费率筛选不会把其他费率的数量清零。显示匹配数与目录总数，并可一键清除筛选。同名模型按名称相邻排列，平台顺序沿用网关配置，便于对比区域费率与能力。费率读取时间集中显示，单模型可在悬停或详情中查看。

页头“数据更新”使用当前页面数据实际取得的时间，不用网关心跳冒充目录更新；费率观察时间仍独立保留。账号可用性矩阵进入、返回、重试及自动刷新均加载所需账号状态；按每个平台自己的模型能力筛选。停用、需登录、账号不可用和未知状态不会显示绿色支持勾。冷却截止锚定数据取得时刻，页面重绘不会重新开始倒计时；倒计时结束显示等待更新，取得新状态前不自行宣布恢复。详情抽屉打开时也暂停自动刷新。

## 统计范围

- 概览的完成调用、成功率、Token 用量与平均生成速度共用所选范围。累计模式保留网关总量；15 / 30 分钟模式只聚合对应的真实分钟桶，生成速度用有效生成 Token / 生成时长计算，不平均每个桶的速度。
- 流量卡独立显示窗口完成调用、平均每分钟调用与窗口 Token。累计模式下仍显示所选分钟窗口；切到分钟模式后与核心指标同步。当前分钟尚未结束，平均 RPM 是窗口完成调用 / 返回的分钟桶数，并非即时吞吐预测。
- 空窗口的调用量与 Token 为零，成功率和生成速度显示 `—`；尚未取得数据或没有分钟桶时显示 `—`，不把数据缺失解释为零。没有完成调用的趋势区显示明确空态。
- 响应表现的 P50 / P95 始终来自最近记录样本，旁边单独展示累计平均完整耗时，注明样本最新记录时间。累计调用分布显示前四项及其占全部分组调用的比例，可点击联动最近日志；这些区域不随核心指标的分钟范围切换。
- 平台就绪数以已启用账号为分母，状态条单独区分就绪、需关注与停用。停用或凭证失效账号不会因残留健康标记计入就绪。
- 用量分析首屏使用网关全部已保存的累计指标，默认可见，不受最近 200 条日志或每日筛选影响。其后的每日分析区域使用独立的按天聚合，区域内的时间、平台、指标、曲线、环图和模型明细口径一致；启用指标落盘时，两类数据都可以跨网关重启保留。
- 调用日志只保留最近 **200 条**，时间筛选、导出、样本成功率、P50 / P95 及账号日志均作用于这些记录。累计失败数与最近失败数可能不同。
- 概览趋势来自最近 **30 分钟**的真实分钟桶，前端可切换显示 15 / 30 分钟。用量分析使用独立的每日趋势，最多保留 **366 个日历日**。当前分钟完成调用数不是滚动一分钟速率。
- 累计模型与账号分组沿用原始模型名和账号标签，可能合并不同平台的同名项。账号标签跨平台重复时，账号表格用量显示 `—`，避免错误归因；平台限定的日志仍能准确筛选。
- 输出速度只使用有生成时长记录的样本；平均耗时是完整调用耗时，包含回复生成，并非首字延迟。
- 可用性矩阵表示目录能力与冷却状态，不代表剩余额度。控制台尚不提供费用估算或额度查询；保留窗口之外的逐日历史无法查询。

## 每日趋势与历史覆盖

每日曲线参考 [ZCode 的用量统计交互](https://github.com/zai-org/ZCode/blob/aac4755666d09fdcd70272fcf063c077a639015f/packages/ui/src/settings/usage-stats/AppUsageDailyModelTrendChart.tsx)，采用现有静态前端独立实现，不引入图表 CDN 或额外构建工具。实现决策与参考源码见[用量统计设计](design/2026-10-15-usage-insights.md)。

- `/api/metrics` 的 `usage_history` 返回 `timezone`、`tracking_since`、`legacy_requests`、`retention_days` 和每日 `days[].models[]`。按实际平台和实际模型组合隔离，不以客户端别名或裸模型名合并。
- 日历边界统一使用 **UTC**，图表和日期明细均标注时区。请求完成后按请求的开始日期归集，包括失败请求已有的用量。Token 总量为输入 + 输出；思考 Token 通常属于输出，不重复相加。
- 近 7 / 30 天包括当前 UTC 日期；「全部记录」从窗口内最早的留存记录 / 采集时间开始，最长 366 天。热力图独立展示这一年度保留窗口，并沿用所选平台。
- 曲线显示前六个模型和「其他模型」，其他项包含剩余模型全部用量，纵轴由可见曲线的峰值确定。点击图例隐藏只改变曲线展示，不改变总量或环图；鼠标、触屏点击和键盘方向键均可查看日期明细。
- 活跃天数按有完成调用的日期计算（包括零 Token 的失败），连续天数只表示所选范围内的观测结果；不推断聊天时长、会话数量或完整历史活跃天数。
- 旧指标文件只有累计量与最近 200 条调用。首次运行新版时只回填这些真实样本，未留存的日期用低对比虚线格和「无数据」标记表示；不能将它们解释成零。首日从启用时间开始，属于部分记录。已回填数据随落盘保存，后续重启不会重复累计。
- 旧版后端的每日分析只能展示已留存的最近请求样本，在趋势标题旁标为「最近 200 条样本」，统计口径中说明覆盖范围；原有历史累计总量和模型分组照常在首屏展示。需要升级后端才能进行长期按天采集。仅刷新网页不会启用后端日历史保存；升级需要重启后端。
- Token 统计仅反映经过网关的请求，不等于上游积分扣费或账单，也不包含客户端直接连接其他供应商的调用。

## 热力图的每日 / 每周 / 累计

热力图右上角提供与 ZCode 相同的三种展示方式，同时保留独立的 Token / 调用指标：

- **每日**：每格对应一个 UTC 日期，颜色代表当日已记录用量；点击查看模型明细。
- **每周**：每列按周日到周六汇总，以填充高度和颜色表示周总量；边缘周可能不足七天。
- **累计**：每列表示保留窗口起点到该周的累计，不能解释成全部历史累计。包含未知日期时仍显示部分覆盖，不补造历史用量。

低对比虚线格表示缺少日期记录。圆点格表示有调用证据，但旧日志没有 Token 明细；这类日期的 Token 曲线会断开，可切换「调用」查看已记录次数。累计指标保持首屏显示，归档来源在统计口径中展示。

## 实时生成

`GET /api/live` 与其他管理接口使用相同鉴权，只返回在途计数、平台 / 模型、累计输出字符、近期速度、采样时间及最近结算结果，不保存或返回对话正文。

自动刷新模式下，用量页每秒读取一次轻量生成快照，页面隐藏、弹窗打开或切换手动模式时暂停；手动刷新会取得一份新快照。各请求结束、失败、取消后都会从实时列表移除。

上游 IR 当前只在结束事件返回精确 Token。生成中先显示实际字符进度 / 字符速度；若已有同平台同模型的成功结算样本，则按输出字符 / Token 比例提供 `≈` 标注的估算进度与速度，不能用于账单。流结束后使用上游正式 Token，最近完成速度沿用实际生成耗时口径。校准只记录计数，不保存输出文本，并随指标持久化。

## 恢复本地旧统计存档

可在本地 `config.json` 明确指定只读历史来源：

```json
{
  "metrics_history_imports": ["bin/history-archive.json", "bin/old-proxy.log"],
  "metrics_history_log_timezone": "+08:00"
}
```

路径相对进程工作目录。来源只在启动时读取，来源文件不改动；日志时区必须明确填写。只恢复 366 天保留范围内的实际日期记录，不读取 ZCode 会话、正文或凭证。导入结果、源内容指纹和记录指纹随指标落盘，多次启动或重叠快照不会重复导入。

旧 JSON 快照的实际最近记录会进入日历史，其累计总量只单独列示：无法完全确认与当前计数是否重叠时，直接相加会误计。完成日志只能恢复有据可查的调用 / 成败次数，Token 未保存则明确标未知；已有精确快照的日期不再叠加时间戳精度较低的日志，宁可保留部分覆盖，也不重复计算。旧日志按完成日志的落盘日期归集，实时采集仍按请求开始日期归集。

历史来源仅应保存在本地忽略目录（如 `bin/`），不要提交包含真实统计、账号标签、错误详情的存档。

## 不重启正在运行的网关

常规网关将前端编入二进制。已有网关进程无法直接加载新静态资源，可单独运行控制台连接它：

```powershell
go build -o bin/agent2api-console.exe ./cmd/console
./bin/agent2api-console.exe -listen 127.0.0.1:8788 -upstream http://127.0.0.1:8787 -assets internal/web/static
```

打开 `http://127.0.0.1:8788/`。该进程从指定目录读取页面，并将 API 请求转发给原网关，逐块刷新 SSE。原网关、账号池、指标、鉴权、路由与 ZCode 地址无需改变。界面复制的 API 地址取自网关状态，仍然是 `8787`，不会误复制控制台端口。

控制台只默认监听回环地址。API 鉴权保持原网关行为。文件变更后刷新页面即可；独立控制台退出不影响原网关。下次正常重新构建并启动网关时，新界面也会自动嵌入其原控制台端口。

## 模型费率

页面按资源到达顺序更新，本地统计与账号状态不等待上游目录。`GET /api/models` 直接返回当前目录快照，需要更新时后台读取；`GET /api/models?refresh=1` 等待本次刷新。各平台并行读取，同一时刻的刷新请求合并，每个平台保留自己的成功目录与刷新状态；响应中的 `catalog_status` 表示各平台目录的读取结果。

零积分卡片按平台分别显示数量，目录缺失或更新失败时提供对应平台状态。模型列表的「调度状态」列显示当前平台账号上的模型冷却、最早可恢复时间和就绪账号数，支持「限流模型」与「有就绪账号」筛选。同名国内与国际模型分别计算；部分账号冷却而其他账号就绪时显示「部分限流」，倒计时结束后等待服务端确认。零积分与限流是独立状态。

WorkBuddy 国内与国际适配器从 `GET /v3/config` 读取 `credits`，不发送聊天请求来判断收费。目录项的 `pricing` 保存来源、读取时间和原始标注，按 **平台 + 模型** 区分；同名模型在不同平台可以有不同倍率。

- `x0.00` 显示 **零积分**；只表示当前目录的积分倍率为零，仍受账号权限与用量限制。
- 正的 `x…` 或 `x… credits` 显示 **积分计费**及倍率；不是人民币或美元的每 Token 单价，不能据此估算金额。
- 未提供固定倍率、且上游明确说明随自动选择浮动时显示 **浮动倍率**。
- 空值、不认识的格式或缺少信息显示 **费率未知**；不从调用成功、模型名或账号额度错误猜测收费。

模型详情显示原始费率标注及完整读取时间；超过 **5 分钟**或本次读取未重新确认的费率归为未知，旧倍率仅作为上次记录。确认依据是上游目录观察时间，而不是页面收到响应的时间；某个平台拉取失败时，网关保留的旧目录不会重新被标成免费。目录来自用于获取目录的账号，上游套餐或活动变化可能影响费率。

原生网关通过 `/api/models` 返回费率元数据。页面可见、自动刷新开启且没有打开详情或弹窗时，控制台每 **60 秒**调用现有的 `POST /api/config {"refresh_models":true}` 使目录缓存失效，再读取模型与费率，避免被默认 30 分钟目录缓存拖延。手动“刷新”或“更新模型与费率”立即重新读取。页面隐藏、详情 / 弹窗打开或手动刷新模式会暂停自动检查；返回可见页面时检查是否需要更新，费率过期仍会改为未知。

按平台 + 模型比较本页面最近确认的费率，免费变付费、积分倍率变化、固定与浮动费率切换会显示全站提醒，直到用户点击“已知晓”；同名国内 / 国际模型互不覆盖。提醒与比较记录保留在当前页面会话中。此模式**仅显示和提醒，继续允许付费调用**，不会改模型选择、客户端配置、请求路由或正在生成的响应；每分钟轮询不等同于上游实时推送，也不构成零扣费保证。

对于没有原生 `pricing` 的旧网关，可读取可选的本地历史快照用于参考，但快照不能确认当前免费状态，相关费率归为未知：

```powershell
go build -o bin/agent2api-pricing.exe ./cmd/agent2api
./bin/agent2api-pricing.exe models -config config.json -pricing-snapshot internal/web/static/_model-pricing.json
```

此导出只用现有 access token 读取配置，不刷新或写回凭证，不开启监听，也不生成内容。快照只含平台、模型及费率信息；任一所选平台读取失败时保留原文件。快照被 Git 忽略，名称以下划线开头，不会被 Go 默认静态嵌入规则打进网关二进制。

导出快照不会变成实时费率来源。网关有原生 `pricing` 时优先使用原生数据，不用快照覆盖；读取失败、旧快照或未提供费率的条目显示未知。不能即时刷新模型的旧网关会显示升级提示；当前不提供账号余额查询或总费用估算。

## 验证

```powershell
go test ./cmd/console
node --test scripts/test-console-*.mjs
```

Go 测试验证转发凭据、平台查询参数与请求体、错误状态码、SSE 首块及时输出及静态资源更新。JavaScript 测试验证碎片化 UTF-8 / CRLF、SSE 用量事件、停止读取、尾部帧、Markdown 转义，以及跨平台日志筛选、统计分位数、生成速度、真实趋势窗口与累计排行。CI 同时运行两组前端测试；页面布局与交互还需要浏览器验证。
