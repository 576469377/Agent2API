# Agent2API 架构设计

> 版本：v1（2026-09-15）
> 设计来源：devin2api 的 IR 分层思想 + WorkBuddy 上游实测结论

---

## 一、设计目标

1. **多平台可扩展**：接入第 2、3 个平台时，不动下游协议层
2. **多协议对外**：OpenAI Chat Completions / OpenAI Responses / Anthropic Messages
3. **单二进制交付**：无运行时依赖
4. **够用即可**：不预设限流、面板、WebSocket 等暂不需要的复杂度

---

## 二、核心架构：IR 分层（N+M 而非 N×M）

```
                    ┌─────────────────────────────────────┐
   客户端            │  下游协议层  internal/api/*          │
   ─────────►       │  ├ openai/chat      (编解码)         │
   /v1/chat/...     │  ├ openai/responses (编解码)         │
   /v1/responses    │  └ anthropic/messages(编解码)        │
   /v1/messages     └──────────────┬──────────────────────┘
                                   │  llm.RequestMessages / llm.ResponseEvent
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  IR 层  internal/llm  （零依赖）      │
                    │  请求 IR / 响应事件 / Failure 分类    │
                    └──────────────┬──────────────────────┘
                                   │  Adapter 接口
                    ┌──────────────┴──────────────────────┐
                    │  平台路由  internal/router            │
                    │  modelID / 路径前缀 → Adapter        │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────┴──────────────────────┐
                    │  上游适配层  internal/adapter/*       │
                    │  ├ workbuddy  ← 第一个实现            │
                    │  ├ devin      ← 后续                 │
                    │  └ ...                               │
                    └─────────────────────────────────────┘
```

**铁律**：`api/*` 与 `adapter/*` 互不 import，只通过 `llm` 通信。

## 三、关键接口设计

### 3.1 上游接缝（照抄 devin2api，仅 2 方法）

```go
// internal/adapter/adapter.go
type Adapter interface {
    // Stream 开始一次流式生成，返回事件流
    Stream(ctx context.Context, req llm.RequestMessages) (llm.ResponseStream, error)
    // ListModels 返回该平台可用模型目录
    ListModels(ctx context.Context) ([]ModelInfo, error)
}

type ModelInfo struct {
    ID             string
    DisplayName    string
    ContextTokens  int
    MaxOutputTokens int
    SupportsImages bool
    SupportsTools  bool
    SupportsThinking bool
    IsDefault      bool
}
```

### 3.2 流接缝（1 方法，能吞下任何上游形态）

```go
// internal/llm/stream.go
type ResponseStream interface {
    Recv(ctx context.Context) (ResponseEvent, error)  // 流结束返回 io.EOF
}
```

这个抽象的价值：上游无论是真 SSE、分页拉取、还是"发任务+轮询状态"，都能塞进来。

### 3.3 响应事件（扁平结构 + 类型枚举）

```go
type ResponseEventType string

const (
    EventStart          ResponseEventType = "start"
    EventTextDelta      ResponseEventType = "text_delta"
    EventTextEnd        ResponseEventType = "text_end"
    EventThinkingDelta  ResponseEventType = "thinking_delta"
    EventThinkingEnd    ResponseEventType = "thinking_end"
    EventToolCallStart  ResponseEventType = "toolcall_start"
    EventToolCallDelta  ResponseEventType = "toolcall_delta"
    EventToolCallEnd    ResponseEventType = "toolcall_end"
    EventDone           ResponseEventType = "done"
    EventError          ResponseEventType = "error"
)

type ResponseEvent struct {
    Type         ResponseEventType
    ContentIndex int
    Delta        string
    ToolCallID   string
    ToolName     string
    Partial      *AssistantMessage  // 每帧累计快照
    Usage        *Usage
    StopReason   StopReason
    Error        *Failure
}
```

### 3.4 结构化错误

```go
// internal/llm/failure.go
type Failure struct {
    Code    string   // 上游错误码，如 "11101"
    Message string
    Cause   error

    // 派生分类
    RateLimited   bool
    ContextLength bool
    Timeout       bool
    Canceled      bool
    ClientFixable bool
    UpstreamFault bool  // 责任在上游（压过 Code 的语义）
}

func Classify(err error) *Failure
```

**一次分类、全程携带**，不在呈现层用正则反推错误语义。

## 四、WorkBuddy 适配器的特殊之处

相比于 devin2api 面对的 Devin，WorkBuddy 上游简单很多，但有几个点必须单独处理：

| 关注点 | 位置 | 说明 |
|---|---|---|
| **认证注入** | [`adapter/workbuddy/auth.go`](../../internal/adapter/workbuddy/auth.go) | 读 `workbuddy-desktop.info` → JWT；过期自动 refresh |
| **强制流式** | [`adapter/workbuddy/client.go`](../../internal/adapter/workbuddy/client.go) | 上游不支持非流式，恒 `stream:true` |
| **非流式聚合** | [`internal/app/app.go`](../../internal/app/app.go) 的 `aggregate` | 客户端要非流式时，在代理侧把 SSE 聚合成单个 JSON |
| **reasoning_content** | [`adapter/workbuddy/sse.go`](../../internal/adapter/workbuddy/sse.go) | ⭐ 映射到 `EventThinkingDelta`（参考实现全漏了） |
| **finish_reason=""** | [`adapter/workbuddy/sse.go`](../../internal/adapter/workbuddy/sse.go) | 删除该字段而非置 null |
| **tool_calls name 回填** | [`adapter/workbuddy/sse.go`](../../internal/adapter/workbuddy/sse.go) | 按 index 缓存 |
| **tool_choice 归一化** | [`adapter/workbuddy/payload.go`](../../internal/adapter/workbuddy/payload.go) | object → string |
| **脱敏** | [`adapter/workbuddy/sanitize.go`](../../internal/adapter/workbuddy/sanitize.go) | 零宽空格 + harness 整段压缩（接入 Claude Code/Codex 必需） |
| **模型清单动态拉取** | [`adapter/workbuddy/models.go`](../../internal/adapter/workbuddy/models.go) | 从 `/v3/config` 拉，缓存 + 硬编码兜底 |
| **DSML 文本态工具调用** | （未实现） | 兜底通道；实测上游走原生 `tool_calls`，暂不需要 |
| **GBK 兜底解码** | [`adapter/workbuddy/client.go`](../../internal/adapter/workbuddy/client.go) 的 `decodeBytes` | `utf-8 → gbk → gb18030 → 替换` |

## 六、里程碑划分

### M1 — 最小可用（建议首个交付）

- [ ] `internal/llm` IR 层
- [ ] `internal/adapter` 接口
- [ ] WorkBuddy 适配器：认证 + 流式聊天 + 模型清单
- [ ] `internal/api/openai/chat`：Chat Completions 编解码（含流式）
- [ ] 非流式本地聚合
- [ ] `cmd/agent2api` 主服务 + 配置
- [ ] 冒烟测试：curl 通 `/v1/chat/completions`

**M1 不包含**：脱敏、多账号池、Anthropic/Responses 协议、面板、限流。

### M2 — 生产可用

- [ ] Anthropic Messages 协议（接 Claude Code 必需）
- [ ] 脱敏模块（接 Claude Code / Codex 必需）
- [ ] `reasoning_content` → `thinking` 完整映射
- [ ] 错误处理与重试（401 刷新重试、传输错误退避）
- [ ] 空闲/总时长双重超时

### M3 — 多平台与运维

- [ ] OpenAI Responses 协议
- [ ] 第二个平台适配器（Devin 或其它）
- [ ] 多账号池 + 冷却 + 熔断
- [ ] Web 管理面板
- [ ] `cmd/probe` 协议漂移检测

## 七、测试策略

借鉴 devin2api 的**金帧回放**：

1. 把真实上游 SSE 样本存进 `fixtures/*.jsonl`
2. 测试时逐帧喂给解码器，断言产出的是 **IR 事件序列**，而不是字节
3. 好处：协议转换可以完全离线测试，不打真实上游

另外：因为 `Adapter` 只有 2 个方法，造假适配器只要 10 行，下游三协议的 HTTP 层测试成本极低。

---

## 八、明确不做（避免过度设计）

- ❌ 限流的分钟桶对齐 / drip 探针（devin2api 的 584 行 rateGate 是对 Devin 的过度拟合）
- ❌ protobuf 逆向工具链（我们上游是 JSON）
- ❌ 六阶段调试日志落盘（第一版用采样日志足够）
- ❌ WebSocket 版 Responses API
- ❌ 多账号池（M1/M2 单账号即可）
