目标是让 Agent2API 成为可以日常使用的多平台网关控制台。以“判断运行状态 → 管理可用资源 → 定位具体失败”为主要路径，同时改进视觉、管理操作和统计表达。当前接入 WorkBuddy 国内版与国际版，界面结构必须容纳后续平台，不能将平台、地区、账号或同名模型混为同一个维度。

## 现状审查

审查了静态网页、数据辅助模块、既有设计记录，并用独立只读预览查看总览、账号、平台、模型、调用列表和详情。预览采用合成数据，包含正常账号、登录失效、失败调用与图片清理记录；没有使用真实凭证或发送生成请求。本机 8787 / 8788 在本次审查时未监听，没有为预览启动真实网关。

| 现状 | 影响 | 优先级 |
|---|---|---|
| 多轮样式调整后，卡片、标题、筛选、按钮的视觉重点不一致 | 页面都存在，但不像统一的产品 | P0 |
| 总览运行诊断位于趋势和分布之后 | 账号不可用或调用失败时，需要滚动才能找到处理入口 | P0 |
| 添加账号等主操作在列表内部，与全局刷新混杂 | 管理操作入口不稳定 | P0 |
| 请求详情是连续的键值列表，错误在最后 | 要先读大量字段才能找到失败原因 | P0 |
| 高级筛选收起后，无法立即看出哪些条件正在影响列表 | 无结果时容易误认为没有数据 | P0 |
| 账号统计只展示数量，不能进入相应列表 | 看到异常后仍需手动选择条件 | P1 |
| 最近 200 条、分钟桶与累计统计并存 | 容易把样本当历史、把不同时间范围混算 | P1：已有范围说明，继续保留 |
| 模型收费信息是积分倍率，缺少实际金额结算数据 | 不能推出费用、余额或真实免费权益 | P2：需要上游计费事实 |

## 分阶段计划与完成标准

### 第一阶段：统一视觉与首屏组织（本轮已实现）

- 统一浅色工作区、深色表面、边框、文字层级和低饱和靛蓝动作色；状态颜色只表达运行事实。
- 导航、页头、搜索、主操作、表格和详情共享同一套变量与尺寸。修改集中在现有 `workbench.css`，不再叠加另一套全站主题文件。
- 核心指标改为连续的四列区域；总览在首屏显示账号关注数与最近样本失败数，并提供入口。
- 页头承载添加账号、客户端接入等主操作；刷新和数据时间作为次级操作。
- 保留深浅色切换、自动刷新、密度与收起导航，不修改用户的已有偏好。

验收：桌面首屏能找到异常入口；浅色和深色均可阅读；390px 宽度时页面本身无横向溢出，宽表在自身区域滚动；未知数据仍显示未知。

### 第二阶段：资源操作与排错闭环（本轮已实现以下部分）

- 账号“就绪 / 需关注 / 已停用”统计可点击筛选，再次点击取消。
- 账号、调用列表展示所有生效筛选，包含收起的高级筛选；支持逐项移除与清空。
- 请求详情优先显示原始错误与有限的操作建议，将耗时、用量、实际路由、图片策略分组展示。
- 请求详情可进入同一平台下的账号或模型调用列表，避免同名资源跨平台混查。
- 横向滚动时保留表格操作列；提供清晰的键盘焦点。
- 不根据含糊的上游 400 文案断言图片超限；缺失图片字段不冒充零张。
- 上游鉴权失败优先于残留身份信息，避免调度列显示需登录而登录列显示已登录；HTML 错误页转换为可读的连接提示，结构化上游错误原文保留。

验收：总览 → 需关注账号，或总览 → 失败调用 → 错误详情均不超过两次点击；清除筛选可恢复记录；自动刷新保留原有输入焦点、滚动位置和高级筛选展开状态。

下一批资源操作：统一模型/账号详情的分组、可选择列及偏好、URL 中可分享且不含敏感数据的筛选状态。账号批量修改需先有独立的选择范围和操作预览，不能在后台刷新中悄悄改变选中集合。

### 第三阶段：可靠统计与运行诊断（需要后端配合，尚未实现）

| 能力 | 前置数据/接口 | 完成标准 |
|---|---|---|
| 任意时间段历史、分页与导出 | 持久化调用记录、服务端时间过滤与分页 | UI 不再把 200 条缓存标作完整历史；查询与导出范围一致 |
| 平台 / 模型 / 账号独立统计 | 平台 ID 与账号稳定 ID 组成聚合键，旧数据迁移或标注 | 国内/国际同名模型不合并；改昵称不丢历史 |
| 首 Token 延迟、建立连接与生成耗时分开 | 请求阶段时间戳及明确测速样本 | TTFT / 总耗时 / tok/s 分母正确，不从总耗时推算 TTFT |
| 换号与换平台尝试时间线 | 脱敏 request ID、每次尝试结果与最终路由 | 一次调用能解释完整经过，日志不保存凭证或请求原文 |
| 实际费用与额度 | 可核实计费单位、账单或账号额度来源 | 积分倍率、货币金额、限额分别表达；无事实时不显示预估账单 |
| 超限策略的可管理配置 | 配置持久化、有效值读取与更新语义 | 明确何时生效、覆盖哪个平台/模型；不能显示未生效开关 |

本阶段应逐项实现和验收，不用模拟图表或假指标填满界面。先完成查询基础，再做统计页面和诊断时间线。

## 验证与发布边界

浏览器审查使用独立端口和模拟数据，真实账号与客户端配置不变。网页资源改动不要求停止现有反代；嵌入网页资源的后端程序需在用户安排的升级窗口重新构建部署。前端测试覆盖原有统计、筛选、费率、刷新及新增错误解释和图片字段语义；视觉验收包含总览、账号筛选、失败详情、模型列表、深浅色和窄屏。测试截图仅用于本地评审，不把模拟数据混入生产接口。

本轮完成 27 项前端测试及 `go test ./...`。390px 模型页与总览页没有整页横向溢出；空数据保持未知成功率 / 生成速度；模拟 HTML 503 提供可读提示和重试。浏览器验证了异常账号入口、清除状态筛选恢复全部账号、失败详情与同平台模型日志联动，正常页面无脚本错误。

验收期间发现本机网关已重新运行。独立控制台在 8788 从磁盘读取最新网页并连接 8787；管理数据加载正常，两个端口的健康接口均返回 200。既有网关进程保持原 PID 和启动时间，没有发送生成请求、修改账号 / 反代策略或客户端配置。
