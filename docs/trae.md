# TRAE 国内版：个人 Free 额度接入

[平台支持](platforms.md) · [配置](configuration.md) · [免费平台调研](research/06-免费账号平台接入调研.md)

`trae-cn` 通过官方网页授权接入个人 Free 账号，不需要购买套餐或提供 API Key。2026-10-23 已用真实普通 Free 账号验证以下三个模型：

| 完整模型 ID | 文本 | 原生工具与结果续轮 |
|---|---|---|
| `trae-cn/deepseek-v4.1-flash` | 已验证 | 已验证 |
| `trae-cn/glm-5.3-flash` | 已验证 | 已验证 |
| `trae-cn/Doubao-Seed-2.1-Turbo` | 已验证 | 已验证 |

三个下游协议均支持流式和非流式回复。工具返回客户端执行，网关不运行 TRAE 桌面 Agent 的终端或文件操作。目录只发布上述已验证模型；DeepSeek 和 GLM 使用当前账号开放的 1M 档位，不透传未知模型、Auto、会员专属模型或自定义供应商。

## 登录与启动

构建当前代码后，在网关所在电脑执行：

```powershell
./bin/agent2api.exe login -platform trae-cn
./bin/agent2api.exe -platform trae-cn
```

打开命令输出的本机链接，在 TRAE 官网完成授权。浏览器与登录命令必须在同一台电脑运行，回调等待最长 30 分钟。旧链接或已经完成的链接不能复用。也可以先启动已配置 `trae-cn` 的网关，在控制台「账号管理 → 添加账号」选择 TRAE 国内版，完成官方网页授权后自动刷新目录。

凭据默认保存到 `~/.agent2api/trae-cn.session.json`，与 WorkBuddy 号池、TRAE 桌面登录文件分开。CLI 可用 `login -platform trae-cn -out <独立路径>` 保存到指定位置；启用时在该平台配置 `credential_path`。同一凭据路径不覆盖其他账号，暂不支持 TRAE 多账号池。访问凭据到期或撤销后，需要重新网页登录；当前没有自动刷新实现。

多平台配置中追加：

```json
{
  "upstream": {
    "platforms": [
      { "id": "workbuddy", "sanitize": true },
      { "id": "trae-cn" }
    ]
  }
}
```

用 `-config config.json` 显式加载。没有配置文件时，`-platform trae-cn` 单独启用；已有显式平台列表时该参数不会替换列表。首次登录不依赖已安装的 TRAE 客户端；如本机已有客户端设备标识则复用，否则只生成并保存一次本网关的设备标识，不因报错、限流或额度不足而轮换。

## 每日自动签到与余额

控制台「账号管理」中的 TRAE 面板显示剩余积分、本期已用与总额、今日奖励、签到状态、下次执行时间、最近结果和余额查询时间。默认启用每天 **北京时间 09:00** 自动签到，可在「签到设置」中暂停或调整时间。

签到在网关后台运行，关闭网页后仍会执行，网关需要保持运行。当天启动时若已过设定时间，会先检查并补执行；已签到则跳过领取。失败后至少间隔 15 分钟重试，每天自动尝试最多 6 次，不更换设备标识。「立即签到（兜底）」仅在当日自动签到失败且等待间隔结束后开放，成功后禁用，避免重复领取。

成功与否以账号签到状态再次查询为准，奖励额度以上游当日返回为准。每次领取前保存恢复记录，领取后核对新增零价通用奖励包与奖励金额，核对完成后才能用于模型调用。超时或重启后先恢复核对，不盲目再次领取。签到配置、恢复记录和已确认的奖励指纹保存在凭据旁的 `.checkin.json` 文件，不包含登录令牌；切换账号后不会沿用旧账号余额和奖励证明。

余额查询失败时保留最近已知余额及更新时间，未取得数据时显示未知。仅领取成功但来源或使用范围尚未确认的奖励会显示待核对，原有免费权益检查继续生效。

## 免费边界

按当前[官方规则](https://docs.trae.cn/ide_plans-and-billing)，普通账号每月登录赠送 **500 积分**；每日签到另有手动领取的奖励。新客一次性赠金、活动、签到奖励与购买积分不是同一种来源。

每次列目录和生成前都会重新查询账号权益，要求个人 Free、非试用、明确关闭按量计费，且当前有效积分包全部来自月度登录赠送或本网关已核对到账的签到奖励。套餐改变、字段缺失、未知来源、查询失败或额度耗尽时拒绝生成，不充值、不升级、不转用购买余额。

新客、邀请及未经过上述到账核对的奖励来源仍不自动放行；签到功能不会把任意零价积分包都认作已验证。付费 / 学生 / 企业权益不作为本适配器的免费依据。

上游积分倍率仍为正数，API 的 `pricing.status` 保持 `credits`，`credit_multiplier` 保留真实目录值。独立 `access` 提供 `plan`、`basis`、`overage_enabled`、`remaining_credits` 和 `checked_at`。控制台显示「免费额度」并保留倍率，ZCode 同步只接收新近确认的免费权益；历史费率快照不能证明当前余额或套餐。

官方目录中的某些条目仍会附带普通身份列表，不能据此推断全部开放。例如 [Seed-Evolving 明确限会员](https://docs.trae.cn/ide_models)，本实现将其排除。

## 参数和用量限制

### 上下文窗口与输出上限

2026-10-23 用普通 Free 账号重新查询上游 `get_detail_param` 的 `solo_agent` 目录，三个已接入模型的可用档位如下。单位均为 Token，K 按 1000 计。

| 模型 | 总上下文窗口 | 输入上限 | 单次输出上限 |
|---|---:|---:|---:|
| `Doubao-Seed-2.1-Turbo` | 256,000 | 224,000 | 32,000 |
| `deepseek-v4.1-flash` | 1,000,000 | 936,000 | 64,000 |
| `glm-5.3-flash` | 1,000,000 | 936,000 | 64,000 |

支持更大窗口且目录包含完整 `__max` 配对时，总窗口来自 `context_window_tokens.max`，输入和输出分别来自对应 `model_detail_list` 的 `prompt_max_tokens`、`max_tokens`，生成也使用该 `__max` 模型。否则使用 `dev` 配对；Seed 仍为 256K / 32K。网关 `/api/models` 的 `context_tokens` 与 ZCode 的 `properties.contextWindow` 使用总窗口；`max_output_tokens` 与 ZCode 的 `optionSpecs.maxOutputTokens.max` 使用输出上限。系统提示、工具定义与历史内容也占用输入空间。

早期版本只查询 `solo_work_lite` 目录，DeepSeek / GLM 只能读到 200K / 32K，遗漏了 `solo_agent` 公开的 1M / 64K 档位。现已修正目录请求与生成模型选择。更大窗口会消耗更多输入积分，仍需在每次生成前通过个人 Free、关闭按量计费、积分来源与余额检查；不购买额度。[官方 Max 模式说明](https://docs.trae.cn/ide_max-mode)介绍了更大上下文的用途与消耗影响。

控制台一键同步与命令行同步均会把这两款模型早期自动写入的 200K 上下文升级到 1M，原默认 32K 输出升级到 64K；其他自定义上下文、更小输出预算、停用状态和其他供应商设置继续保留。若 ZCode 仍显示旧窗口，确认客户端已重新读取供应商配置。

### 参数与用量

- 支持 system、完整文本历史、原生 JSON Schema 工具、工具选择、错误工具结果和思考输出；不静默裁剪历史。
- 图片、JSON 输出模式和 `stop` 返回明确错误。
- **上游不遵守 `max_tokens` / `max_output_tokens`，本网关当前也不截断 TRAE 输出。** 目录的 `max_output_tokens` 仅表示上游公布的上限；实测传 4 仍生成 79 个 completion tokens。需要严格输出预算的客户端应选其他已支持该能力的平台。
- 采样参数和思考开关 / effort 不转发、不保证生效；ZCode 使用固定思考选项，不发送控制指令。
- Token、思考和缓存仅取上游真实报告值。缓存读取是输入 token 的子集，不再加一次；没有最终用量时保持未知。

默认模型上游为 `https://trae-api-cn.mchost.guru`；授权及权益检查固定使用 `https://api.trae.cn`。实现使用固定、实测可用的协议版本字段，不据此宣称本机安装了该版本。私有接口可能漂移，发现变化后应先停止并检查，不通过更换账号或设备标识绕过限制。

## `trae_free_only` 排查

此错误表示网关未能确认完整免费权益，不等于登录失效。先查看 TRAE 账号面板的余额更新时间、免费核验结果与签到最近结果，再查询 `GET /api/accounts/checkin?platform=trae-cn&refresh=1`；刷新只查询状态和余额，并恢复已有领取记录的到账核对，不重新领取。

已修复领取过程中新增积分的生效时间与旧查询时刻比较，导致签到奖励被误判为未来积分的问题。领取后的核对使用新的观察时刻，恢复记录仍须证明奖励来自本次领取、金额一致且免费使用范围完整。未知来源、付费或无法核对的积分继续拒绝；不要通过关闭校验或直接修改奖励证明绕过。

## 验证依据

1M 修复另以同一真实 Free 账号、未启动后台签到的独立适配器执行合成文本测试：DeepSeek / GLM 均完成约 250K 和 900K 输入，上游分别报告 900,103 / 900,084 输入 Token，并正确返回开头、中间、结尾的三个固定测试标记。保留上游原始用量，不将缓存读取重复加到输入。以上验证了接近窗口上限的长输入与标记保留，不等于对 1M 内任意任务质量的保证。

首次协议接入验证于 2026-10-23 在独立端口、独立凭据文件、关闭指标落盘的候选网关上完成：三个模型的文本、原生工具与结果续轮，Chat Completions / Responses / Messages 的流式和非流式，以及上游真实缓存用量观察。当时没有重启原网关、改写原指标或写入正在使用的 ZCode 配置。客户端工具测试仅返回固定测试值。1M 修复发布时另验证了运行中网关的工具调用与结果续轮，并在备份后同步本机 ZCode，仅更新 DeepSeek / GLM 的旧窗口默认值；其他供应商、默认选择和既有使用记录保持不变。

脱敏金帧和权益 / 目录样本见 [fixtures](../fixtures/README.md)，解析、免费拒绝、取消和共享预算回归见 [protocol_test.go](../internal/adapter/trae/protocol_test.go)。脱敏保留数值标识的类型；`timing_cost`、`extra_info`、设备和认证材料不进入公开样本。

授权依据包括官方网页协议与固定提交的 [设备绑定实现对照](https://github.com/jlcodes99/cockpit-tools/blob/76fbea02ba8ab5a071205a0bfa59ef4db5cc64b4/crates/cockpit-core/src/modules/trae_oauth.rs)。网页登录采用 PKCE S256、一次性会话和设备绑定，在兑换前保留本机恢复记录；上游已兑换而资料查询或保存失败时，优先恢复结果，避免反复要求人工授权。
