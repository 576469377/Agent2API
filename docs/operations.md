# 运行、升级与恢复

[文档导航](README.md) · [配置参考](configuration.md) · [指标口径](metrics.md) · [故障排查](troubleshooting.md)

本页面向已经跑通首次回复的用户。首次构建与登录见[快速开始](quickstart.md)。升级时保留现有配置、账号文件和统计目录，客户端仍连接原网关地址。

## 先确认正在使用哪一个进程

| 要确认的事 | 从哪里查看 |
|---|---|
| 网关地址与运行版本 | 控制台侧栏、设置页、`GET /api/status` |
| 本次实际使用的等待预算 | 设置页“请求预算与排队”、`GET /api/config` |
| 当前是否有生成请求 | 用量分析“实时输出”、`GET /api/live` 的 `in_flight` |
| 统计写到哪里 | 用量分析“统计口径”、`GET /api/metrics` 的 `storage` |
| 源码提交 | 源码目录中执行 `git log -1 --oneline` |

磁盘中的新源码、编译好的候选程序和已经运行的进程是三种状态。修改文件不会更新进程中的嵌入式网页或后端代码。页面显示的语义版本也不能替代源码提交编号。

## 只更新控制台界面

在仓库根目录另开终端：

```powershell
go run ./cmd/console -listen 127.0.0.1:8788 -upstream http://127.0.0.1:8787 -assets internal/web/static
```

打开 [独立控制台](http://127.0.0.1:8788)。页面从磁盘加载，API 和流式数据仍来自现有网关；无需中断 ZCode。客户端继续连接 `8787`。

独立控制台可预览新界面，后端新增能力仍需升级网关。例如新版页面能展示上传阶段，但旧后端不会因此开始采集这些阶段。关闭预览终端只停止这一个界面进程。

## 更新网关

当前集成代码在 `main`。先确认工作区没有需要保留的未提交修改：

```powershell
git status --short --branch
git pull --ff-only origin main
go test ./cmd/... ./internal/...
go vet ./cmd/... ./internal/...
go build -trimpath -o bin/agent2api-next.exe ./cmd/agent2api
```

macOS / Linux 将输出文件改为 `bin/agent2api-next`。构建到新文件，不覆盖正在使用的程序。

1. 在设置页记录当前地址、平台列表和统计路径。
2. 等待 `/api/live` 中 `in_flight` 为零，再停止旧网关。正常 Ctrl+C 会停止接收请求，最多等待 15 秒收尾，然后保存统计；已有数分钟的请求未必能在这段时间内完成。
3. 保留旧二进制，使用候选程序和**同一份配置、同一工作目录**启动：`./bin/agent2api-next.exe -config config.json`。
4. 确认累计量、`storage` 和有效预算；在控制台只选确认免费的模型，验证一条回复。
5. 让客户端继续使用原地址。确认稳定后再整理本地候选文件。

有持续请求时先使用独立控制台预览。不要为了界面更新直接强制结束网关；旧请求可能在写出首段前仍在上传图片或等待上游。

## 回退

保留候选失败时的错误码和提交号，等待在途请求结束，停止新程序后，用保留的旧二进制和原配置重新启动。不要同时运行两个写入同一统计文件的网关。

若变更涉及数据格式，先确认旧版本是否理解新字段；本项目新增的可选指标字段不应依赖删除统计文件来恢复服务。回退程序不会恢复上游额度或撤销已经完成的请求。

## 备份与恢复

应备份：

| 内容 | 用途 |
|---|---|
| 实际使用的 `config.json` | 平台、目录、访问密钥、别名和超时设置 |
| 配置的 `auths/` 或其他账号目录 | WorkBuddy 文件账号凭证 |
| `storage.file` 对应的统计快照 | 累计指标和已保存的逐日记录 |
| ZCode 的 `provider_config.json` 及同步备份 | 客户端供应商配置 |
| 当前可执行文件与提交号 | 回退与复现 |

凭证和配置仅保存在自己的受保护备份中，不加入仓库。桌面加密凭证可能绑定本机用户与安装环境；复制文件不保证能在另一台电脑解密。

默认统计路径：

- 显式 `-metrics-file` 或 `metrics_file` 优先。
- 使用 `-config` 时，默认是配置文件同目录的 `metrics.json`。
- 没有配置文件时，默认是工作目录的 `agent2api-metrics.json`。
- 显式相对路径相对进程工作目录解析。

先检查现有存档，不直接覆盖：

```powershell
python scripts/diagnose-console.py --config config.json
python scripts/diagnose-console.py --config config.json --scan-history
```

找到可恢复的旧快照或日志后，按[历史导入配置](console.md#恢复本地旧统计存档)只读导入。交集未知的累计快照不能简单相加；日志中的 Token 日期不能根据请求数猜测。没有留存明细时保留缺口；如需将旧累计量纳入趋势，可使用控制台的历史用量设置，计算方式见“统计口径”。

## 常见维护任务

| 任务 | 建议操作 |
|---|---|
| 新增本人已授权的 WorkBuddy 账号 | 控制台添加对应区域账号；无需重启 |
| 原账号重新授权 | 使用“重新登录”；桌面来源在原客户端处理 |
| 更新模型费率 | 模型目录“同步费率”；不发送生成请求 |
| 更新 ZCode 免费模型配置 | 先运行 `sync-zcode.py --dry-run`，再应用并保留备份 |
| 调整排队、尝试次数和超时 | 修改实际启动配置，在空闲窗口重启 |
| 恢复限流模型 | 遵循上游重置时刻；清除本地冷却不会补充额度 |
| 请求变慢 | 先区分上传、等待响应和接收暂停，再看首段等待与完整耗时 |

## 前置代理与长请求

SSE 需要及时转发数据，前置代理不应缓存响应。HTTP 代理的请求体限制、上传超时和等待响应超时也应容纳实际图片历史，不能只增加 Agent2API 的生成时长。

网关默认接收上限是 256 MiB；它表示传输字节，不等于模型的 Token 上下文。WorkBuddy 默认建流预算为 600 秒，包含排队、上传和等待，不会套用非流式 60 秒总超时。不要通过删除历史、换号或改模型来掩盖一个已确认的本地超时问题。

## 完成维护后

确认后台能读取新配置、历史统计仍在、真实免费模型回复正常、客户端请求走到期望平台。长期排错优先使用[诊断摘要](troubleshooting.md#反馈问题)，不用完整请求或凭证文件。
