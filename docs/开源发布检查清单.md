# 开源发布检查清单

> 每次**对外推送**、**打 tag**、**打包分发**前，请照此逐项执行。
> 目的：确保凭证、个人标识与运行数据不会通过**任何途径**离开本机。

---

## ❶ 首次推送前（只做一次）

### 1. 确认 `.gitignore` 生效

```bash
# 期望：无输出（敏感路径都不该出现在待提交列表）
git status --porcelain | grep -E 'bin/|metrics\.json|\.workbuddy|auths/|\.session\.json|config\.json|\.info'
```

### 2. 安装 pre-commit 钩子（防止以后手滑）

```bash
make hooks
# 或：cp scripts/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

### 3. 脚手架检查：确认 git 里没有任何敏感文件

```bash
# 期望：无输出
git ls-files | grep -E 'bin/|metrics\.json|\.workbuddy|auths/|\.session\.json|config\.json|\.info$'
```

---

## ❷ 每次推送前（必做）

### 4. 凭证扫描 —— 最关键的一步

```bash
# 期望：无输出
git log --all -p | grep -E 'eyJ[A-Za-z0-9_-]{20,}|sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}'
```

> ⚠️ 注意是 `git log --all -p` —— 扫的是**全部历史**，不只是当前工作区。
> 一旦凭证进了历史，即使后来的提交删掉了它，**旧提交里仍然能看到**。

### 5. 个人标识扫描

```bash
# 期望：无输出
git log --all -p | grep -E '<账号昵称>|/Users/<用户名>'
```

### 6. 真实上游 ID / 时间戳扫描

```bash
# 期望：无输出
git log --all -p | grep -E '1789482[0-9]{3}|1789484[0-9]{3}|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}'
```

### 7. 不可达对象扫描（重建历史后尤其重要）

```bash
# 期望：0
git cat-file --batch-all-objects --batch-check | awk '$2=="blob"{print $1}' \
  | while read o; do git cat-file -p "$o" 2>/dev/null; done \
  | grep -cE '<账号昵称>|/Users/<用户名>|eyJ[A-Za-z0-9_-]{20,}'

# 若无用对象，可清理（谨慎：会重写所有提交哈希）
# git reflog expire --expire=now --all && git gc --prune=now --aggressive
```

### 8. 构建与测试

```bash
make check          # fmt + vet + test
make test-race
```

## ❸ 打包分发前（zip / tar / 容器）

> ⚠️ **`.gitignore` 只保护 git，不保护 tarball。**
> `git archive` 会遵守 `.gitignore`，但 `zip -r .` / `tar czf .` **不会**。

### 9. 用 `git archive` 打包（推荐，自动排除未跟踪文件）

```bash
git archive --format=tar.gz --prefix=Agent2API/ -o /tmp/Agent2API.tar.gz HEAD
# 验证产物内容
tar tzf /tmp/Agent2API.tar.gz | grep -E '^bin/|metrics\.json$|\.workbuddy/|^auths/|\.session\.json$|^config\.json$|\.info$' \
  && echo "❌ 含敏感文件" || echo "✅ 干净"
```

### 10. 若必须手工打包，显式排除

```bash
zip -r Agent2API.zip . \
  -x 'bin/*' 'agent2api-metrics.json' 'metrics.json' '.workbuddy/*' \
     'auths/*' '*.session.json' 'config.json' '*.info' '.git/*'
```

### 11. 发布二进制时用 `-trimpath`

`make build` 已包含。

```bash
# 验证二进制不含本机绝对路径
strings -a bin/agent2api | grep -c "/Users/"   # 期望：0
```

## ❹ 推送 / 发布

### 12. 确认远端地址正确

```bash
git remote -v
```

### 13. 首次推送

```bash
git push -u origin main
```

### 14. 推送后立刻复查（用 GitHub 网页端）

- 确认仓库首页 **Commits 数量**符合预期（不该有多余的历史提交）
- 确认没有 `.workbuddy/`、`bin/`、`agent2api-metrics.json`
- 确认 README 渲染正常、链接可达

## ❺ 万一已经泄漏了

**如果凭证被推上去了 —— 第一件事是轮换凭证，不是删仓库。**

1. **立即轮换**：在 WorkBuddy/CodeBuddy 客户端退出登录并重新登录，使旧 token 失效
2. 再清理历史：
   ```bash
   # 用 git-filter-repo（推荐）或 BFG 清除指定文件/字符串
   git filter-repo --replace-text <(echo '泄露的字符串==>REDACTED')
   git push --force --all
   ```
3. GitHub 上旧提交可能仍可通过 API/缓存访问一段时间 → 联系 GitHub Support 清理缓存
4. 若涉及公开 fork，需通知 fork 者或申请 DMCA 删除

> **教训**：凭证必须在**进入历史之前**就被拦住。这也是 `scripts/pre-commit` 存在的原因。
