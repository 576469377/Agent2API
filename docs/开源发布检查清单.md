# 开源发布检查清单

> 每次**对外推送**、**打 tag**、**打包分发**前，请照此逐项执行。
> 目的：降低误发布凭证、个人标识与运行数据的风险。自动扫描覆盖常见路径和格式，不能证明所有自定义秘密都不存在。

---

## ❶ 首次推送前（只做一次）

### 1. 确认 `.gitignore` 生效

```bash
# 期望：无输出（敏感路径都不该出现在待提交列表）
git status --porcelain | grep -E 'bin/|metrics\.json|\.workbuddy|auths/|\.session\.json|config\.json|\.info'
```

### 2. 安装 pre-commit 钩子（防止以后手滑）

```bash
make hooks
# 或：cp scripts/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

### 3. 脚手架检查：确认 git 里没有任何敏感文件

```bash
# 期望：无输出
git ls-files | grep -E 'bin/|metrics\.json|\.workbuddy|auths/|\.session\.json|config\.json|\.info$'
```

## ❷ 每次推送前（必做）

### 4. 凭证扫描 —— 最关键的一步

```bash
# 检查暂存内容与已跟踪文件，不输出命中的密钥值
python scripts/check-secrets.py --staged
python scripts/check-secrets.py --tracked
# 检查全部可达历史，包括后来删除的文件
python scripts/check-secrets.py --history
```

> 注意使用 `--history` 扫描**全部可达历史**，不只是当前工作区。检查结果只显示路径、位置和类型，不回显疑似凭证。
> 一旦凭证进了历史，即使后来的提交删掉了它，**旧提交里仍然能看到**。

### 5. 个人标识扫描

```bash
# 期望：无输出
git log --all -p | grep -E '<账号昵称>|/Users/<用户名>'
```

### 6. 真实上游 ID / 时间戳扫描

下方只列出候选项，须人工区分真实标识与 `fixtures/` 中已脱敏的合成 UUID；普通 UUID 命中不等于凭证泄漏。

```bash
# 人工核对候选项及来源
git log --all -p | grep -E '1789482[0-9]{3}|1789484[0-9]{3}|[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}'
```

### 7. 不可达对象扫描（重建历史后尤其重要）

```bash
# 期望：0
git cat-file --batch-all-objects --batch-check | awk '$2=="blob"{print $1}' \
  | while read o; do git cat-file -p "$o" 2>/dev/null; done \
  | grep -cE '<账号昵称>|/Users/<用户名>|eyJ[A-Za-z0-9_-]{20,}'

# 仅在确认无需恢复任何旧对象后清理；这会删除恢复记录和无引用对象，不会重写现有提交哈希
# git reflog expire --expire=now --all && git gc --prune=now --aggressive
```

### 8. 构建与测试

```bash
make check          # fmt + vet + test
make test-race
```

## ❸ 打包分发前（zip / tar / 容器）

> ⚠️ **`.gitignore` 只保护 git，不保护 tarball。**
> `git archive` 只打包指定提交的已跟踪文件，**不会自动排除误提交的敏感文件**；`.gitignore` 也不能移除已经跟踪的文件。`zip -r .` / `tar czf .` 会包含未跟踪的本地文件，需显式排除。

### 9. 用 `git archive` 打包（推荐，自动排除未跟踪文件）

```bash
git archive --format=tar.gz --prefix=Agent2API/ -o /tmp/Agent2API.tar.gz HEAD
# 验证产物内容
tar tzf /tmp/Agent2API.tar.gz | grep -E '^Agent2API/(bin/|auths/|\.workbuddy/|\.zcode/)|/(provider_config\.json[^/]*|config\.json|config\.(local|dev|prod)\.json|[^/]*\.session\.json[^/]*|[^/]*\.info[^/]*|(agent2api-)?metrics\.json[^/]*|\.env[^/]*)$' \
  && echo "发现敏感路径候选项，请核对" || echo "未发现上述路径；仍需核对文件内容"
```

### 10. 若必须手工打包，使用明确的文件清单

不要直接打包整个工作目录后依赖少量排除规则：自选名称的凭证、客户端配置、临时文件和备份可能被遗漏。优先对已通过历史扫描的提交使用 `git archive`；确有额外文件时单独审查后加入，并检查最终产物。

### 11. 发布二进制时用 `-trimpath`

`make build` 已包含。

```bash
# 验证二进制不含本机绝对路径
strings -a bin/agent2api | grep -c "/Users/"   # 期望：0
```

## ❹ 推送 / 发布

### 12. 确认远端地址正确

```bash
git remote -v
```

### 13. 首次推送

```bash
git push -u origin main
```

### 14. 推送后立刻复查（用 GitHub 网页端）

- 确认仓库首页 **Commits 数量**符合预期（不该有多余的历史提交）
- 确认没有 `.workbuddy/`、`bin/`、`agent2api-metrics.json`
- 确认 README 渲染正常、链接可达

## ❺ 万一已经泄漏了

**如果凭证被推上去了 —— 第一件事是轮换凭证，不是删仓库。**

1. **立即撤销或轮换**：使用对应平台提供的撤销会话、密钥或授权功能，并确认旧凭证失效；仅重新登录不保证旧 token 已撤销。
2. 再安排历史清理：与维护者确认受影响文件、提交和分支，用 `git-filter-repo` 或 BFG 清除；避免把真实秘密直接写入命令或终端输出。历史重写会影响协作者，需要协调后更新受影响分支。
3. GitHub 上旧提交可能仍可通过 API/缓存访问一段时间 → 联系 GitHub Support 清理缓存
4. 若涉及公开 fork，联系持有副本者协助清理；历史清理不能替代凭证撤销。

> **教训**：凭证必须在**进入历史之前**就被拦住。这也是 [`scripts/pre-commit`](../scripts/pre-commit) 存在的原因。
