# 故障排查

[文档导航](README.md) · [快速开始](quickstart.md) · [配置](configuration.md)

先查看控制台「调用日志」中的平台、请求模型、实际模型与错误，再检查「账号管理」的凭证和调度状态。`/health` 只检查本地进程，不验证上游额度。

| 现象 | 检查与处理 |
|---|---|
| 首次启动没有账号 / `no_available_accounts` / 503 | 新版会保留空账号池，在「账号管理 → 添加账号」完成对应区域登录；也可执行 `login -region cn/global`。显式配置只保留所选平台 |
| 未登录过国际版，登录入口缺失 | 旧版会在启动时跳过无凭证的平台，此问题需要新版后端修复，仅更新控制台页面无效；检查运行的二进制版本及显式平台配置，已有反代在使用时安排空闲时段更新 |
| 国际加密凭证读取失败 | 确认 WorkBuddy AI 安装位置；自定义安装使用 `AGENT2API_WORKBUDDY_EXECUTABLE`；不要手动导出明文 token |
| 控制台提示 `Invalid API key` | 使用实际运行配置中的网关密钥，在控制台设置中重新验证；本地存储的旧密钥不会自动随配置修改 |
| 页面能打开，但 API 失败 | 静态页面无需鉴权，API 可能需要密钥；独立控制台还需要能够连接原网关 |
| 新控制台打不开 / 502 | 检查独立控制台端口、`-upstream` 和 `-assets`；不必停止原网关，见[控制台](console.md) |
| `address already in use` | 已有程序占用端口；已有网关正在使用时，连接原进程或启动独立控制台，不要重复启动 |
| 国内与国际同名模型选错区域 | 改用 `workbuddy/模型名` 或 `workbuddy-global/模型名`；裸名优先级取决于平台配置顺序 |
| 模型在目录里但生成失败 | 检查账号权限、额度和上游实际服务；目录条目不保证当前可用 |
| 旧对话 / 切换模型后 HTTP 400，提示参数被模型供应端拒绝 | 通用错误不指出具体字段；用[临时诊断入口](request-diagnostics.md)取得参数和历史结构摘要，无需停止反代，勿上传原始请求、密钥或完整对话 |
| 429 / 额度不足 / 14018 | 查看上游错误；账号「可调度」不表示还有额度。固定平台不会跨区回退，裸名回退需显式开启 |
| 401 / 账号 blocked | 在原桌面客户端或号池登录流程中恢复凭证；清冷却不会增加额度，也不会修复真实无效凭证 |
| `Illegal API invocation from an unapproved channel` | 使用当前网关代码并保留默认内容脱敏，检查是否仍运行旧二进制 |
| ZCode 原有模型不见了 | 检查是否加载了有效配置，查看本地备份与日志；使用增量同步脚本，避免手工覆盖整份配置 |
| ZCode 出现旧模型名或未立即更新 | 等待客户端重新读取配置；查看日志中的 schema 错误；同步不会自动删除历史模型 |
| 并发多时等待或频繁限流 | 默认每账号 4 并发；矩阵可查看在途 / 上限。持续限流时适当调低，见[并发配置](configuration.md#并发上限max_concurrency_per_account) |

## 界面更新了，网关还是旧行为

网关把静态资源嵌入二进制；正在运行的进程不会因源码或产物改变而自动更新。独立控制台只更新展示，API、路由与账号处理仍由原网关完成。需要升级后端时安排正常重启；不要把前端刷新当成网关升级。

## 会话没有固定账号

会话路由键按顺序使用请求头、body 的 `metadata.user_id` / `user`，再回退到「系统提示 + 首条用户消息」哈希。前置代理若丢弃会话头，可能影响亲和；例如 Nginx 默认丢弃带下划线的请求头，需按自己的代理配置处理 `session_id`。账号不可用时也可能换号，亲和不保证所有请求永久固定在同一账号。

## 非流式为何等待完整生成

上游使用流式输出，网关聚合后才返回非流式响应。需要逐块看到内容时使用 `stream: true`，并确认前置代理没有缓存 SSE。

## 反馈问题

提供提交编号或版本、操作系统、平台区域、协议、模型路由形式、最小复现和脱敏后的错误。不要发送完整配置、凭证、账号昵称、密钥或上游请求 ID。漏洞按[安全策略](../SECURITY.md)私下报告。
