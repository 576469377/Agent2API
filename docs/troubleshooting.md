# 故障排查

[文档导航](README.md) · [快速开始](quickstart.md) · [配置](configuration.md)

先查看控制台「调用日志」中的平台、请求模型、实际模型与错误，再检查「账号管理」的凭证和调度状态。`/health` 只检查本地进程，不验证上游额度。

| 现象 | 检查与处理 |
|---|---|
| 首次启动没有账号 / `no_available_accounts` / 503 | 新版会保留空账号池，在「账号管理 → 添加账号」完成对应区域登录；也可执行 `login -region cn/global`。显式配置只保留所选平台 |
| 未登录过国际版，登录入口缺失 | 旧版会在启动时跳过无凭证的平台，此问题需要新版后端修复，仅更新控制台页面无效；检查运行的二进制版本及显式平台配置，已有反代在使用时安排空闲时段更新 |
| 国际加密凭证读取失败 | 确认 WorkBuddy AI 安装位置；自定义安装使用 `AGENT2API_WORKBUDDY_EXECUTABLE`；不要手动导出明文 token |
| 控制台提示 `Invalid API key` | 使用实际运行配置中的网关密钥，在控制台设置中重新验证；本地存储的旧密钥不会自动随配置修改 |
| 页面能打开，但 API 失败 | 静态页面无需鉴权，API 可能需要密钥；独立控制台还需要能够连接原网关 |
| 新控制台打不开 / 502 | 检查独立控制台端口、`-upstream` 和 `-assets`；不必停止原网关，见[控制台](console.md) |
| `address already in use` | 已有程序占用端口；已有网关正在使用时，连接原进程或启动独立控制台，不要重复启动 |
| 国内与国际同名模型选错区域 | 改用 `workbuddy/模型名` 或 `workbuddy-global/模型名`；裸名优先级取决于平台配置顺序 |
| 模型在目录里但生成失败 | 检查账号权限、额度和上游实际服务；目录条目不保证当前可用 |
| WorkBuddy 返回 `request illegal` / `upstream_11128` | 上游业务码 `11128` 的说明是“请求被拦截，请重新发送”。更新网关后可保留业务码及 `displayMsg`；这句通用拒绝不能直接证明图片超限、额度耗尽或账号封禁。用官方客户端对照相同账号的简单请求；模型目录可读、凭证健康也不保证生成接口接受请求 |
| OpenRouter Dots 提示 `Provider returned error` / HTTP 400 | 2026-10-19 实测其免费端点拒绝目录标称的 `max_tokens=460800`，相同测试使用 8192 可以开始回复；重新运行 ZCode 同步脚本，修复已有规则的输出预算。新版错误会补充供应端名称和经脱敏的错误原因，其他 400 仍需按实际原因排查 |
| OpenRouter 所有免费模型都报 `free-models-per-day` / 429 | 表示账号每日免费调用额度耗尽，切换 OpenRouter 免费模型不增加额度。可通过官方 `GET /api/v1/key` 查看 `free_model_daily_requests`；等待恢复或主动选择其他平台的免费模型。免费限制见 [OpenRouter 文档](https://openrouter.ai/docs/api_reference/limits)，失败尝试也可能计入额度 |
| Cursor 工具续接变成 `<tool_call>` 普通文本，或只执行第一步就结束 | 更新网关后端。旧实现把历史工具调用拼成文本；新版改用结构化历史、完整工具描述，并已验证 ZCode 多轮工具调用。原生规则和其他未声明的主机操作限制仍见 [Cursor 配置](configuration.md#cursor个人-free-额度) |
| 旧对话 / 切换模型后 HTTP 400，提示参数被模型供应端拒绝 | 先看包含历史与工具结果的图片总数：国际版 Hy3 内置护栏 200、Step 60，国内版不套用；见[图片护栏配置](configuration.md#单请求图片数量护栏modelsimage_limits)。同一英文也可能由坏图等其他原因触发，未超限时不要断言原因；再用[结构诊断](request-diagnostics.md)排查，勿上传密钥或完整对话 |
| ZCode 超限后反复发「继续」仍失败 | 「继续」仍携带同一份历史图片。默认拒绝模式不会删除历史；接受省略最旧图片时，可显式启用[续聊策略](configuration.md#旧对话超限后的续聊策略modelsimage_overflow_policies)，保留最近图片、文字和工具结果，本地记录不变；更新后端程序和配置后才生效 |
| 429 / 额度不足 / 14018 | 查看上游错误；账号「可调度」不表示还有额度。固定平台不会跨区回退，裸名回退需显式开启 |
| 401 / 账号 blocked | 在原桌面客户端或号池登录流程中恢复凭证；清冷却不会增加额度，也不会修复真实无效凭证 |
| `Illegal API invocation from an unapproved channel` | 使用当前网关代码并保留默认内容脱敏，检查是否仍运行旧二进制 |
| ZCode 原有模型不见了 | 检查是否加载了有效配置，查看本地备份与日志；使用增量同步脚本，避免手工覆盖整份配置 |
| ZCode 出现旧模型名或未立即更新 | 等待客户端重新读取配置；查看日志中的 schema 错误；同步不会自动删除历史模型 |
| 并发多时等待或频繁限流 | 默认每账号不限并发，可显式配置正数排队上限；矩阵可查看在途 / 上限。短时请求过密可考虑降低并发，但不能恢复已经耗尽的用量窗口，见[并发配置](configuration.md#并发上限max_concurrency_per_account) |

## 国际版提示 frequency limit / will reset at

例如 `usage exceeds frequency limit ... your usage will reset at ... UTC+8` 表示上游明确给出了模型使用窗口的重置时间。仅凭 `429` 状态码无法确定是 RPM、Token、滚动窗口还是其他模型配额；不要把它直接认定为并发连接数超限或积分余额归零。

网关识别国内版「将在 … 重置」和国际版 `will reset at …` 的时间，按明确的时区冷却对应账号上的对应模型（最长 24 小时）。其他模型保持可用；固定平台模型不会擅自改换模型或跳到其他区域。没有可解析的重置时间时不推测冻结时长。旧后端仅识别中文，国际版可能反复碰到同一个 429，需要更新后端。

并发上限控制同时在途请求，不能替代 RPM / TPM 或长周期额度管理。已经触发明确重置时间时，原样反复重试或仅降低并发都不会保证恢复；应等待上游重置，或主动选择其他可用模型。

代理服务商也可能返回 429，所以应结合完整错误正文和错误页来源判断。梯子流量耗尽常伴随代理拒绝、连接失败或超时；上面这种带模型重置时刻、建议换模型的业务提示更支持上游限制的判断。网络恢复和模型窗口恢复是两件独立的事，不通过故意发送生成请求来验证额度。

## 界面更新了，网关还是旧行为

网关把静态资源嵌入二进制；正在运行的进程不会因源码或产物改变而自动更新。独立控制台只更新展示，API、路由与账号处理仍由原网关完成。需要升级后端时安排正常重启；不要把前端刷新当成网关升级。

## 更新后只剩今天用量 / 两台电脑目录不同

已使用多天、升级后只剩当天时，先核对实际读取的统计文件，不要覆盖或删除旧文件。同样的 WorkBuddy 账号不会在网关之间同步统计；但也不能用这一点解释已有历史在升级后消失。

在**出现问题的网关所在电脑**、按启动网关时相同的工作目录执行：

```powershell
python scripts/diagnose-console.py --config config.json
```

如实际使用 `-metrics-file` 或其他端口，添加 `--metrics-file 原路径 --url http://127.0.0.1:实际端口`。脚本只读管理 API 和本地统计文件，不发送生成请求、不刷新登录、不写文件；输出只包含耗时、数量、日期、存储路径和状态，不含密钥、账号名称、请求正文或原始错误。不要提交真实诊断输出。

- `usage.dates` 与 `local_statistics[].dates`：比较内存历史、当前文件、旧文件的日期范围。旧版无 `usage_history` 时，`recent_dates` 仅代表留存的最近请求日期，不能代表全部使用日期。
- `storage.file / loaded_from / last_saved_at`：新版后端实际写入位置、启动时来源、最近成功写入时间。`load_error / save_error` 表示读写异常；旧后端没有这些字段。
- `endpoints`：本地统计已返回而模型接口耗时长，通常是目录读取链路等待；新版控制台不再让这些资源互相阻塞。
- `catalogs`：逐个平台核对模型和零积分数量、目录错误。`accounts` 只汇总平台账号状态和模型冷却，不输出账号身份。不要把目录缺失、费率未知和限流都解释为收费变化。

默认路径：带 `-config` 时使用配置文件同目录的 `metrics.json`，无配置时使用工作目录的 `agent2api-metrics.json`；显式 `metrics_file` / `-metrics-file` 优先，相对路径仍以进程工作目录为准。新版仅兼容**同目录**的两个默认文件名：当前文件缺失时从另一个加载；当前文件已存在时，另一个文件只补充未覆盖的历史日期，不相加交集未知的累计总量。现代快照使用完整逐日聚合，不受最近 200 条限制；旧文件只有最近样本时不能重建未保存的 Token 日期。

统计文件损坏时，新版保留原文件并写入独立的 `.recovery` 文件，状态可在「用量分析 → 统计口径」查看。跨目录部署、容器未挂载旧数据目录、关闭持久化或旧文件已被覆盖，需要根据诊断结果找回原数据 / 备份，不能仅凭账号登录态恢复。

累计量仍在、但 `usage.dates` 与当前文件都只有最近一天时，可进一步查找旧存档：

```powershell
python scripts/diagnose-console.py --config config.json --scan-history
```

此选项只检查项目根目录及 `bin / logs / data / backups / archive` 直属目录中的指标快照与反代日志，不遍历凭证目录、不修改文件。输出 `tracking_since`、`legacy_requests` 和实际逐日调用数以区分旧累计量与新采集日期；日志只输出完成行数量及日期，不输出原始行、账号或错误。日志日期保留其原时区，导入时仍需明确配置日志时区。若找到旧文件，按[历史恢复配置](console.md#恢复本地旧统计存档)只读导入；没有旧日期数据的累计计数无法还原逐日 Token。

需要将缺少日期的历史量纳入趋势时，可使用控制台默认的[历史均摊](console.md#历史均摊)：将差额均摊到采集前 30 天并标记估算，支持自定义范围或仅实测。分摊不会增加累计总量，也不改写原始文件；诊断 API 继续反映实际留存日期。

## 会话没有固定账号

会话路由键按顺序使用 body 的 `session_id`、会话请求头、`prompt_cache_key`、`metadata.user_id` / `user`，再回退到「系统提示 + 首条用户消息」哈希。前置代理若丢弃会话头，可能影响亲和；例如 Nginx 默认丢弃带下划线的请求头，需按自己的代理配置处理 `session_id`。账号不可用或达到并发上限时也可能换号，亲和不保证所有请求永久固定在同一账号；网关重启后会重建内存中的绑定。

## 缓存命中为零或客户端看不到缓存

先确认使用包含缓存用量修复的网关版本。旧版 WorkBuddy 误读了输出明细中的 `cached_tokens`，且 Messages / Responses 与 Chat 非流式未完整返回缓存用量，可能使客户端显示零命中。新版从输入明细及明确的上游别名读取缓存数，并保留各协议的读写统计，见 [API 缓存口径](api.md#提示缓存与用量)。

反代不会为了同一会话逐轮随机更换系统提示；WorkBuddy 的内容转换是确定性的，现有有效会话会优先使用原账号。但缓存是否生效仍由上游决定，客户端发送缓存标记并不等于所有平台都支持。一次上游明确返回零命中只代表该次请求；重复请求被限流时也不能据此判断缓存失效。排查时使用同一账号、同一免费模型和足够长的固定前缀，读取上游实际用量，避免通过更换账号反复请求来判断命中率。

## 非流式为何等待完整生成

上游使用流式输出，网关聚合后才返回非流式响应。需要逐块看到内容时使用 `stream: true`，并确认前置代理没有缓存 SSE。

## 反馈问题

提供提交编号或版本、操作系统、平台区域、协议、模型路由形式、最小复现和脱敏后的错误。不要发送完整配置、凭证、账号昵称、密钥或上游请求 ID。漏洞按[安全策略](../SECURITY.md)私下报告。
