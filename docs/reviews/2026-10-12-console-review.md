# 控制台显示逻辑复查 · 2026-10-12

[控制台说明](../console.md) · [核心逻辑审查](2026-10-12-proxy-logic-review.md)

本轮从 `0062f23` 的前端出发，检查资源页、数据取得时间、筛选作用域和账号可用性。以下修改只更新网页资源，没有重启网关或控制台，没有改账号、密钥、路由或客户端地址。

## 已处理的问题

| 问题 | 本轮修正 |
|---|---|
| 缓存的冷却秒数在重绘时加到当前时间，倒计时被延长 | 记录每份数据取得时间，截止时间始终由原始快照计算；结束后等待新的后端状态，不凭倒计时自行恢复支持勾。账号卡片、表格和矩阵采用同一边界。 |
| 矩阵页自动刷新只取得网关状态，重试遗漏矩阵，返回页面遗漏账号 | 集中定义页面依赖；进入、返回、手动刷新和重试加载模型、账号和矩阵；自动刷新加载账号与矩阵。 |
| 停用、鉴权失效和未知账号仍可能显示目录支持勾 | 先判断账号状态，再判断目录支持和模型冷却；整号冷却留在列头，不展开成每格相同倒计时。 |
| 同名跨平台模型的能力合并后参与矩阵筛选 | 目录按平台保留事实，每列只使用该列来源平台的能力；目录和矩阵共用搜索及能力筛选。 |
| 页头更新时间来自网关心跳，旧目录看起来一直在更新 | 页头以本页实际数据取得时间显示；费率观察时间独立保留。宽度超过 720px 时保留可见的数据时间。 |
| 详情抽屉打开时仍在后台刷新 | 抽屉和弹窗均暂停自动刷新；未承诺取消打开前已经发出的请求。 |
| 模型目录费率信息平铺，缺少筛选作用域与恢复入口 | 增加费率数量概览及联动、匹配数、清除筛选；概览遵循平台、能力与搜索，费率筛选单独联动结果。 |
| 同名模型因全路由 ID 排序分散，时间字段重复占用行高 | 先按模型名，再按配置中的平台顺序排列；费率记录时间集中显示，单项时间保留在悬停和详情，表格更紧凑。 |
| 模型清单更新被误认为重新取得本地费率快照 | 明确显示快照性质；按钮改为“更新模型清单”，成功提示说明费率读取时间保留；刷新失败不发成功提示。 |
| 账号页面切换平台后，概览数量仍来自全部平台 | 概览按当前选中的平台统计，平台切换数量仍反映全部目录。 |

模型目录的绿色勾仅表示目录支持，不保证账号有剩余额度，也不保证下一次请求成功。零积分、积分倍率与账号余额继续分开表达；过期费率按已有规则归为未知。本轮仅读管理 API 和已有费率快照，没有发送聊天请求测试额度。

## 验证

18 项离线前端测试覆盖流式、日志统计、费用元数据，以及新增的刷新依赖、固定冷却截止、账号不可用优先级、跨平台筛选和页面时间边界。浏览器验证了数量概览联动、清除筛选、同名模型排列、矩阵加载及页面错误日志。修改后的网页资源还需通过 Go 构建和既有 CI。

## 仍需后端支持的改进

- **可查询的完整调用历史**：当前最近 200 条不是任意时间段的历史，前端不应提供没有数据支撑的长期筛选。
- **换号与换平台的尝试记录**：最终结果不足以解释一次请求的完整路线，需要请求 ID 与脱敏的逐次尝试记录后再做时间线。
- **平台与账号隔离的累计统计**：原始模型名及账号标签仍可能跨平台合并，必须先迁移后端统计维度再展示独立用量。
- **同一时刻的一致资源快照**：账号管理和模型矩阵目前来自独立接口；快速状态变化时可能短暂不一致，前端不能把它们解释成事务快照。
- **自动更新旧网关的费率记录**：当前不重启模式读取显式导出的本地快照；新网关原生目录支持 `pricing` 后随目录缓存刷新。前端本身无法替旧进程补上接口。

这些项目继续沿用核心逻辑审查的优先级，不用装饰性组件模拟尚未提供的数据。
