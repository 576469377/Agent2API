# 反代核心逻辑审查 · 2026-10-12

[文档导航](../README.md) · [当前架构](../architecture.md) · [配置](../configuration.md)

本轮以 Agent2API 提交 `6b0fe70` 为审查基线，对照三个开源项目的调度、失败处理、并发与路由源码。目标是完善多平台本地网关的正确性与可维护性。下面区分已经修复的缺陷、保留的行为和后续实现项。

源码修复需要重新构建并启动网关才能生效。本轮不替换正在使用的后端，也不修改本地账号、密钥或 ZCode 配置；独立控制台仍连接原网关。

## 本项目应保持的不变量

1. **平台选择与账号选择分层**：Hub 选择平台，Pool 选择该平台内的账号，协议编码器不认识 WorkBuddy 凭证或账号池。
2. **明确路由优先**：`平台/模型` 和指定平台的别名固定来源；裸模型的跨平台回退保持显式开关。
3. **亲和不绕过检查**：会话绑定是候选偏好，不是另一套错误分类；HTTP 满载时可以使用其他空闲账号。
4. **流接受后不重放**：当前边界保守地设在上游流被接受；中途断流通过流内错误返回。将来支持有上游状态的 Responses 或 WebSocket 时，必须单独定义不可迁移绑定。
5. **取消终止上游尝试**：已取消请求不再选号或建流，本地取消不降低账号健康度。
6. **等待时间属于请求的模型**：同一账号的账号级与模型级冷却都结束才可用；池级等待取这些账号中最早的可用时刻。
7. **状态与原因分开**：人为停用、鉴权失效、模型限流、本地并发占满应分别呈现，不能全部标成“限流”。
8. **冷却作用域由平台事实决定**：当前 WorkBuddy 模型冷却规则不应自动推广到未来上游。没有重置依据时不编造额度倒计时。

## 本轮发现与修复

以下行为由离线假适配器与 HTTP 测试验证，不调用真实上游，不消耗模型额度。

| 缺陷 | 原行为与影响 | 修复后的行为 |
|---|---|---|
| 绑定账号有独立失败路径 | 401 不标记账号失效，429 不写模型冷却，参数错误也继续换号；绑定成功没有更新同一套健康度。 | 绑定仅决定首选候选；建流、健康度与错误分类全部进入普通尝试循环，每个账号在该请求中最多尝试一次。 |
| 软亲和把请求排在满载账号后 | 即使另一账号有空闲槽位，也等待绑定账号直到取消。 | 满载绑定退出首选路径，优先使用其他可用容量；全池满载仍按现有并发槽位等待。 |
| 已取消请求仍可能发起调用 | 无并发限制或槽位已空闲时，假适配器仍收到请求。 | 在进入调度、每次尝试和取得槽位之后检查取消；取得槽位后取消会立即归还。 |
| 全池不可用判定读取裸冷却表 | 与冷却写入或账号新增并发时存在竞态；读取过程不是一致的调度快照。 | 在同一池锁下检查账号、冷却与终态。新增并发读写回归测试。 |
| 等待时间取错模型与边界 | 其他模型的短冷却影响当前模型；账号级与模型级取较早者，可能提前唤醒。 | 单账号取当前模型与账号级截止时间的较晚者，跨账号取最早值；忽略停用与永久鉴权失效账号；正的不足一秒等待向上取整。 |
| 停用被误报为限流 | 全部手动停用返回 429；“一个停用、一个鉴权失效”也返回 429。 | 无启用账号或空池返回 503；所有启用账号鉴权失效返回 401；真实模型冷却返回 429。 |
| 会话哈希缺少有效输入 | 对空内容计算 SHA-256，空哈希仍有固定值；Responses 的 `input` 未参与，Chat 的消息内 system 未参与。 | 无会话内容返回空键；识别 Responses 字符串与消息数组、instructions、Chat system/developer；首条用户内容在后续轮次中保持稳定。显式会话头继续优先。 |
| 回退最终错误归因不正确 | 后续平台也失败时，仍返回第一个平台的错误并记录第一个平台。 | 返回最后实际尝试的平台与错误；固定平台和已接受的流仍不跨平台。 |
| 等待建议未贯通客户端 | HTTP 日期形式的 `Retry-After` 未识别，JSON 错误响应未发送等待头；超大秒数可导致时长乘法溢出。 | 接受秒数及 HTTP 日期，拒绝无效值并限制到 24 小时；429 / 503 在有正等待建议时发送 `Retry-After`；时长在乘法前封顶。 |
| 随机调度测试的样本假设不成立 | 冷启动健康分随成功样本变化，60 次不能当作固定概率的独立抽样；曾出现功能分支偶发失败。 | 保留原份额下限断言，将样本扩大到 1000，并关闭每次取得的流；不通过放宽断言掩盖调度问题。 |

同步清理了失效的冷启动常量、错误等待辅助函数及重复的头解析函数。`is_next` 为兼容保留，但其注释明确是推荐账号，不能预测加权随机调度的下一次结果。

### 已保留的行为

- 未知裸模型仍透传默认平台，避免仅因目录缓存尚未更新而拒绝新模型。
- 模型目录刷新失败时，Hub 保留该平台最后一次成功目录。
- 不因未知额度重置时间而人为冻结当前 WorkBuddy 账号。
- 本地并发槽位占用持续到流关闭或读取结束；同一流的释放仍保持幂等。
- 控制台统计的最近 200 条记录与累计指标继续分别标注；本轮不宣称已经实现完整历史日志。

## 下一阶段的实现顺序

下表是本轮审查结论与建议，**尚未实现**。这些设计需要配置、管理 API 与测试共同落地，不能只给控制台加一个开关。

| 优先级 | 能力 | 当前缺口 | 验收要求 |
|---|---|---|---|
| P0 | 请求级重试预算 | 适配器最多重拨 3 次、Pool 换号、Hub 换平台分别计数；账号变多后一次请求的总尝试数和延迟仍可能膨胀。 | 建立跨层共享的尝试数与时间预算；区分连接重拨、刷新凭证、账号切换和平台切换；取消及流接受立刻终止重试。 |
| P0 | 有界排队与槽位预留 | 当前队列只受请求 context 约束；流式调用排队发生在适配器总超时开始之前；选号与占槽不是同一次预留。 | 限制等待人数和排队时间；同一临界区内选取并预留容量；排队超时返回明确 503；取消、错误、结束都释放，压力测试验证不会超额。 |
| P1 | 每次尝试的追踪 | 日志只有最终结果，难以解释“为什么换号、换了几次、时间花在哪里”；首轮失败尚不能完整归因到账号。 | request ID 串联脱敏的 attempt 记录；记录平台、稳定账号 ID、阶段、状态、等待、建流和总耗时；禁止写入密钥、凭证和原始请求内容。 |
| P1 | 按平台隔离的统计与持久化历史 | 累计模型名和账号标签会跨平台合并，最近记录受 200 条上限约束；累计快照中的计数与分组也需检查一致性。 | 使用平台与稳定资源 ID 联合维度；迁移旧数据时保留无法确定归属的部分；历史查询分页、保留期与删除策略明确，累计值与明细范围分别说明。 |
| P1 | 账号级模型能力与目录快照 | Pool 当前从一个健康账号取得目录，默认同平台目录相同；换号前未按各账号目录筛选。 | 缓存每账号目录及取得时间；区分支持、不支持、未知；候选过滤与同名平台回退共用模型能力事实，刷新失败不误删有效模型。 |
| P1 | 平台特定故障作用域 | 当前限流处理主要来自 WorkBuddy 经验，未来平台可能按账号、模型、组织或区域限流。 | 适配器返回结构化的故障作用域、重置依据与可重试性；统一调度消费这些字段；本地故障退避与上游额度冷却分开显示。 |
| P2 | 凭证刷新失败的可见状态 | 已有刷新锁与失效处理，但缺少统一的刷新退避状态、恢复原因及管理指标。 | 同一凭证刷新合并；刷新中、临时失败、永久失效分别可观察；恢复后重新验证目录与调度资格，持久化失败不暴露凭证内容。 |

用户计费、分组配额、多用户 RBAC 与分布式调度可以在需要共享服务时另立范围。目前更应先完成预算、排队和可观测性，使增加平台与账号不会增加不可解释的失败。

本轮新增测试覆盖绑定账号的 401 / 429 / 参数错误、满载绑定逃逸、取消、当前模型的冷却截止、停用与失效区分、冷却并发读写、等待头、时长溢出、三协议会话键与回退最终归因。既有三协议、区域隔离、工具调用、SSE 和并发生命周期测试仍需一起通过。

本机完整普通 Go 测试、vet、构建、10 项前端测试及 9 项脚本测试已通过；重点调度回归另重复 20 轮通过。本机现有 MinGW 编译器不支持 64 位模式，无法完成 `-race` 构建；竞态验证由现有 Linux/macOS、Go 1.23 与 stable 的 CI 矩阵执行。暂存内容、跟踪文件及可达历史的密钥扫描均无发现。

对已有使用中的网关，本轮只构建独立的新二进制作准备。正在运行的进程保持原版本；安排后续正常切换时，再启用这些后端修复。不要以控制台已更新推断后端逻辑也已热更新。
