## 2. 认证刷新与保活

原代码注释称网络刷新在锁外，实际 `Refresh` 全程持有认证互斥锁。上游迟迟不响应时，普通请求构造认证头、读取账号状态及重新登录都要等待。两个重叠的强制刷新还可能串行旋转两次令牌。

新实现将网络请求、短暂状态锁和凭据提交分开：同一凭据共享一次在途刷新；网络和文件写入不占用读取凭据的锁；文件替换与版本提交单独串行。读取者使用不可变快照，未过期令牌可继续使用，需要新令牌的调用等待刷新结果。

取消与重新登录需要分别处理：单个等待者可以取消自己的等待；全部等待者离开后取消共享请求，但旧 HTTP 尚未结束时保留其占位。已完整返回的成功令牌旋转仍要保存，避免丢掉新的 refresh token。新登录一旦成功提交，旧刷新无论成功或失败都不能覆盖它。刷新保存失败保留已旋转的新内存令牌；重新登录保存失败则保持之前的登录态。

另一个问题是保活接口没有接通：循环断言无参数 `EnsureValid()`，WorkBuddy Adapter 没有实现该接口，真实适配器因此被跳过。现在适配器暴露带 context 的保活入口，保活调用同时受单次预算与服务取消约束。

离线复现包含：阻塞刷新期间读取认证头、并发重新登录、重叠强制刷新、等待者取消、迟到旋转结果、旧会话成功 / 失败、持久化失败以及真实适配器进入保活循环。没有改写用户凭据或执行真实登录。

## 3. 排队、冷却与会话缓存

### 冷却到期不会主动唤醒排队者

复现场景：账号 A 正在服务且占满容量，账号 B 有空闲容量但模型尚在冷却。新请求进入队列后，只监听容量释放和总排队超时。B 的冷却自然到期没有通知，因此即使它已能接收请求，排队者仍可能报 `queue_timeout`。

现在复用已有队列计时器，在原排队截止时间与最早可用账号恢复时间之间选择更早者。账号级和目标模型级冷却取较晚时间；已尝试、停用、鉴权失效及满容量账号不参与恢复唤醒。计时器到点只触发重新选号，不重置排队总预算。

### 亲和表满时丢失成功迁移

4096 条绑定达到容量后，旧 `set` 连已有键的更新也拒绝。某会话因原账号满载成功迁移到空闲账号，下一轮却回到旧绑定，影响上下文在同一账号的连续使用。现在已有键可直接更新和续期；新键继续受原容量约束。没有修改上游 prompt、缓存字段或缓存计费。

### 选号减少临时分配

旧选号构建全部候选和空闲候选两份切片。现在在同一临界区先累计总权重与空闲权重，再按相同顺序抽样。空闲优先、最低权重、停用 / 冷却过滤和概率分布保持一致。相关队列、容量、亲和和健康度回归均继续覆盖。

实现：[queue.go](../../internal/adapter/queue.go)、[pool.go](../../internal/adapter/pool.go)、[affinity.go](../../internal/adapter/affinity.go)。

## 4. 统计恢复与保存

- **缺失恢复文件提前返回。** `Metrics.Load` 把文件不存在视为正常首次启动；恢复选择器错误复用该语义，在基础 `.recovery` 不存在时返回，跳过已有带时间戳的有效恢复文件。回归在旧版得到调用数和 Token 均为零。现在确认文件存在后才选用，否则按既有顺序继续找最新有效恢复快照。
- **null 被接受为空快照。** JSON `null` 解码到结构体不报错，原流程因此忽略有效恢复文件。现在明确要求对象，保留原文件并进入恢复流程。恢复选择完整快照，不相加可能重叠的累计历史。
- **周期任务没有退出条件。** 保存循环改为随服务 context 退出，重复启动不会创建多个 worker。正常关闭及超时关闭仍在请求最终结算后保存；已有保存锁防止周期保存与最终保存互相覆盖。
- **不再保存缩进副本。** 文件仍是同一 JSON 数据结构，仅省去机器快照不需要的空格与换行。累计、每日、模型、缺失 Token 标记和导入信息保持原值。

实现：[metrics_storage.go](../../internal/app/metrics_storage.go)、[metrics.go](../../internal/obs/metrics.go)。

## 5. 控制台刷新与实时数据

旧普通目录请求与主动费率核验各自发布结果。离线测试让新核验先返回付费状态、旧请求后返回免费状态，最终页面错误回到旧目录。账号操作后的刷新也会因“当前正在加载”直接跳过，使页面继续显示操作前状态。

现在按资源管理在途请求：普通刷新复用同一 Promise；主动刷新与操作后的更新取消并替换旧读取。除 AbortSignal 外还校验任务身份，因此不遵守取消、已经进入解码或迟到的响应也不能覆盖新状态。认证更换会使旧资源请求失效，旧 401 不得修改新认证状态。

实时请求使用同样的机制。离开分析页或隐藏页面会取消当前读取并释放 busy；返回页面可以马上开始新读取，旧采样即使稍后到达也不进入实时曲线。

曲线点按用量快照和指标复用；隐藏某条曲线只更新可见性，不重新扫描所有日期和模型。新快照、日期或筛选变化产生新派生对象，重新计算。旧后端只提供 recent 样本时，缺失 Token 的记录补回未知标记，明确上报的零仍按零处理。

实现：[resources.js](../../internal/web/static/resources.js)、[app.js](../../internal/web/static/app.js)、[usage.js](../../internal/web/static/usage.js)。测试除独立模块外，还从生产 app.js 提取实际刷新函数，执行受控的目录竞争、操作后刷新和实时读取流程。
