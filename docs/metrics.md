# 指标与数据口径

[文档导航](README.md) · [控制台](console.md) · [API](api.md) · [运行与升级](operations.md)

控制台展示的是网关实际保存和接收的数据。累计计数、逐日记录、最近请求样本、实时观测各有范围；它们不能互相替代。页面没有对应观测值时显示“—”或“未记录”，不会补成测得零值。

## 四类数据

| 数据 | 来源 | 范围 | 适合回答 |
|---|---|---|---|
| 累计指标 | `/api/metrics` 顶层及 `by_model` / `by_protocol` / `by_account` | 已载入并保存的全部累计量 | 一共调用了多少、各模型用了多少 |
| 每日用量 | `usage_history.days` | UTC 日期，最多 366 天 | 某天、某个平台或模型的用量 |
| 调用样本 | `recent` | 最近完成的 200 条；列表时间为请求发起时间 | 某次调用为何失败、近期耗时和缓存表现 |
| 实时状态 | `/api/live` | 当前请求及页面最近 30 秒采样 | 正在上传、等待响应还是接收输出 |

“近期调用”只取最近 200 条中、发起时间落在近 15 分钟的已完成记录。高流量下可能没有覆盖全部 15 分钟；很久以前发起、刚完成的长请求也不属于这一发起时间窗口。它不会使用累计失败数推断“现在仍在失败”。

## 调用次数与状态

- 一次客户端生成请求计一次调用。内部连接重试、换账号或平台回退记录在 `attempts`，不额外增加逻辑调用量。
- 请求完成后才归入 `total`、`ok` 或 `failed`；当前请求在 `in_flight` 和实时列表中。
- 累计 `failed` 包括客户端取消。调用日志另外区分“失败 · 不含取消”和“客户端取消”，两者相加等于未成功样本数。
- 记录中的 499 表示客户端停止等待或断开。`routing_timeout`、`queue_timeout`、`upstream_header_timeout` 是不同原因，不能都解释为客户端取消。
- `last_minute_rpm` 按最近 60 秒进入网关的生成请求计算，包含仍在进行中的请求；它不是累计调用数除以运行分钟数。
- HTTP 流开始后不能改写已经发出的 200 响应头。流内错误仍会使该条观测记录标为失败；应同时看流内错误和日志状态。

目录查询、账号检查、控制台刷新和健康检查不计入生成请求量。

## 等待时间与速度

| 字段 / 展示 | 起止点 | 缺失或限制 |
|---|---|---|
| `duration_ms` 完整耗时 | 网关接到请求至处理结束 | 包含读取、解码、排队、上传、上游等待、接流和写回 |
| `queue_ms` 排队等待 | 本地账号容量等待 | 新请求无排队时为零；旧记录可能未采集 |
| `attempts[].duration_ms` 尝试等待 | 一次上游生成尝试开始至建流完成或失败 | 包含上传和响应等待，不是完整回答时长 |
| `first_output_ms` 首段等待 | 请求到达至首段非空文本、思考或工具参数 | 没有产出或旧记录缺失时不参与分位数 |
| `gen_ms` 接收耗时 | 取得上游流至用量接收结束 | 包含网络停顿和客户端背压；不是模型内部解码时间 |
| 完成接收速度 | 上游报告的输出 Token ÷ 对应 `gen_ms` | 只使用输出与耗时均有测量的记录 |
| 实时字符/s | 最近 3 秒实际收到的字符数 ÷ 窗口时长 | 含文本、思考和工具参数；没有新字符可为零 |
| `≈ tokens/s` | 同平台、同模型的字符 / Token 校准 | 估算值；没有校准样本时展示字符/s |

P50、P95 使用所选请求样本的最近秩分位数。完整耗时和首段等待分别筛选自己的有效观测值，不能用缺失值充当零来降低 P95。“上次测得速度”来自最近一条有最终输出和接收时长的成功记录，附完成时刻，不表示当前速度。

## 实时阶段

| `phase` | 页面显示 | 已知事实 |
|---|---|---|
| `reading` | 正在读取请求 | 正在接收或解析客户端请求 |
| `routing` | 正在选择服务 | 选择平台、账号或准备下一次尝试 |
| `queued` | 排队等待 | 已触发本地并发上限，等待账号容量 |
| `connecting` | 正在连接上游 | 生成尝试已开始，尚未观测到请求头写出 |
| `uploading` | 正在上传请求 | 请求头已写出，请求体尚未完成写出 |
| `waiting_headers` | 等待上游响应 | 本次请求已写出，等待上游响应头 |
| `waiting_output` | 等待首段输出 | 上游响应已接受，尚无非空输出 |
| `streaming` | 正在接收 / 等待后续输出 | 按最后一次实际输出时间区分活跃与暂停 |

传输阶段来自 HTTP 客户端回调。请求写出不等于上游已经完成预处理，等待响应也不能证明模型正在推理。双向流的上传结束回调可能晚于响应；已接受的流不会被迟到回调改回上传阶段。

默认自动刷新时，实时接口约每秒读取；普通资源按页面的 10 / 30 / 60 秒间隔刷新。手动模式、后台页面或打开详情时会暂停相应轮询。实时快照超过 5 秒没有更新会标为过期；断开的采样点不会连接成连续曲线。

## Token 与提示缓存

总 Token = 输入 Token + 输出 Token。思考 Token 已包含在输出中，不能再次相加。

| 协议 | 总输入与缓存读取 |
|---|---|
| Chat Completions | `prompt_tokens` 已包含缓存；细分见 `prompt_tokens_details` |
| Responses | `input_tokens` 已包含缓存；细分见 `input_tokens_details` |
| Anthropic Messages | 普通 `input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens` 相加才是总输入 |

调用日志中的“缓存读取 / 输入”按有缓存用量依据的样本加权计算：这些样本的缓存读取 Token 总和 ÷ 同一批样本的输入 Token 总和。不是逐条百分比的简单平均，也不是命中过缓存的请求占比。旧记录未保存缓存数时不当作零命中；详情会显示未记录。

`usage_reported: true` 表示本次实际收到上游用量；明确报告的零和没有报告不同。网关不保存完整回答以复用，也不会把首次请求伪装成缓存命中。提示缓存是否生效由上游决定，详见 [API 缓存说明](api.md#提示缓存与用量)。

逐日用量的 `unknown_token_requests` 记录有输出但没有 Token 用量的调用，例如当前 Kiro ACP 接口的调用。前端按模型与日期处理：有已记录 Token 就继续展示，仅完全缺少 Token 的模型曲线留空。包含这类调用的合计以 `≥` 表示已记录用量，不影响其他平台、模型或日期的统计。

## 历史缺口与均摊估算

旧版快照可能只有累计量，没有逐日 Token。累计量可以恢复，但不能据此还原真实日期分布。

控制台可将缺少日期的差额均摊到采集前的指定区间，并按既定历史归属计入国内版 `workbuddy/deepseek-v4.1-flash`。这是浏览器派生视图，原始统计文件和累计总量保持不变。

- 趋势、日历与读数直接显示用量；“统计口径”提供归集区间、数量和目标模型。
- 从“统计口径 → 统计设置”选择“全部用量”或“仅每日记录”，并调整均摊日期；重新计算不会叠加两次。
- 活跃天数与连续活跃按实际调用记录计算，不把均摊产生的请求当成真实活跃。
- 估算日期不能用于证明某天真实调用了某个模型，也不会生成可查询的单次请求日志。
- 没有逐日依据的空白不等于当天实测为零；只保留调用量、没有 Token 明细的日期单独说明。

恢复旧存档见[运行与升级](operations.md#备份与恢复)；界面入口见[控制台](console.md#历史均摊)。

## 持久化与隐私

`storage` 提供当前文件、载入来源、保存状态和最近保存时刻。`ready` 表示当前存储链路可用，`load_error` / `save_error` 需要检查文件权限和路径。损坏原件会被保留，恢复写入使用独立文件，不直接覆盖原件。

记录可能包含模型、区域、账号标签、时间和用量，统计文件应视为本地私有数据。新增尝试记录只保留账号摘要，不保留凭证或消息正文；“复制诊断摘要”进一步排除账号标识、自由文本错误、文件路径、请求头和对话内容。
